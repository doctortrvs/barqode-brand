# 07 — Iconography

> This document defines the principles that govern iconography throughout the Barqode ecosystem.
>
> Barqode does not use icons as decoration.
>
> It uses symbols to communicate information before language.

---

# Philosophy

An icon exists to visually communicate a key message, action or place.

Its purpose is to reduce thinking.

A successful icon should allow an operator to understand the category of a message before reading the accompanying text.

Barqode does not treat icons as illustrations.

It treats them as a visual language.

Every icon should communicate with clarity, consistency and purpose.

---

# Recognition Before Reading

Operators should recognise information before they consciously begin reading.

Recognition is significantly faster than reading.

Every symbol should therefore communicate its category before its specific meaning.

The objective is simple:

> An operator should recognise the category of a message before reading a single word.

This principle should apply across every Barqode product, regardless of platform or device.

---

# Recognition Hierarchy

Every symbol communicates in four layers.

## 1. Shape

The shape communicates the category.

> "What type of message is this?"

---

## 2. Icon

The icon communicates the specific meaning.

> "What exactly is this about?"

---

## 3. Colour

Colour communicates severity, status or priority.

> "How important is this?"

---

## 4. Text

Text provides complete context.

> "What do I need to know or do?"

Each layer reinforces the next.

No single layer should carry the entire message.

---

# Shape Language

Barqode uses a small number of consistent shapes.

Each shape represents a category of communication rather than a specific message.

Shapes should never be chosen because they look attractive.

They should be chosen because operators already understand them through decades of exposure to road signage, airport wayfinding, industrial safety systems and international standards.

---

## ● Circle

**Meaning**

Status

Circles communicate condition rather than instruction.

Examples include:

- Online
- Offline
- Connected
- Pending
- Complete
- Active

A circle tells the operator what state something is currently in.

---

## ▲ Triangle

**Meaning**

Warning

Triangles indicate caution before continuing.

Examples include:

- Errors
- Hazards
- Missing information
- Failed operations
- Validation problems

A triangle should immediately communicate:

> Pay attention before continuing.

---

## ■ Square

**Meaning**

Information

Squares communicate information that helps the operator complete work but does not necessarily require immediate action.

Examples include:

- Information
- Guidance
- Mandatory instructions
- Operational notes

Squares should feel stable, neutral and dependable.

---

## ▬ Rectangle

**Meaning**

Direction

Rectangles communicate navigation and movement.

Examples include:

- Continue
- Next step
- Route
- Location
- Navigation
- Workflow direction

Rectangles help operators understand where to go rather than what has happened.

---

## ◆ Diamond

**Meaning**

Special Condition

Diamonds communicate that something differs from the normal operational flow.

Examples include:

- Exceptional handling
- Restricted shipments
- Dangerous goods
- Priority processing
- Manual review

A diamond communicates:

> This requires additional awareness.

It does not necessarily indicate a problem.

---

# Shape Consistency

The outer shape should always communicate the category.

Only the icon inside should change.

For example:

```
▲ !
▲ Truck
▲ Barcode
▲ Package
```

Each remains a warning.

The icon simply communicates what the warning relates to.

This allows operators to learn the language quickly.

Shape communicates category.

Icon communicates meaning.

---

# Icons

Icons should communicate specific concepts inside a consistent category.

Barqode should use familiar, recognisable symbols wherever possible.

The objective is not originality.

The objective is immediate recognition.

Where an internationally recognised symbol already exists, it should generally be preferred over creating a new one.

Barqode should borrow from the physical world wherever practical.

Examples include:

- Warehouses
- Road signage
- Airport wayfinding
- Industrial control systems
- Safety signage
- Logistics equipment

Operators should feel familiar with the system before learning it.

---

# Colour

Colour reinforces meaning.

It should never create meaning.

Every symbol should remain understandable when viewed:

- In black and white
- On poor-quality displays
- By colour-blind users
- In printed documentation

Shape should communicate category.

Colour should communicate state.

If colour is removed, the symbol should still make sense.

---

# Filled and Outlined

Filled and outlined symbols communicate different levels of emphasis.

## Filled

Filled symbols represent:

- Active
- Current
- Live
- Selected
- Requires attention

They naturally attract the eye first.

---

## Outlined

Outlined symbols represent:

- Passive
- Reference
- Navigation
- Supporting information
- Available options

Outlined symbols should create less visual weight while remaining recognisable.

---

# Motion

Motion should be used sparingly.

Icons should never animate simply because animation is available.

Constant movement creates distraction and visual fatigue, particularly within operational software that remains open throughout the working day.

Motion should communicate genuine change.

Appropriate examples include:

- Progress
- Synchronisation
- Loading
- Live activity

Attention should be earned through importance rather than animation.

---

# Notification Counts

Notification counts should always appear adjacent to the symbol.

They should never be placed inside the shape.

This ensures notification counts remain readable regardless of size.

Examples:

```
▲ 4

● 18

■ 126
```

This approach scales naturally without compromising legibility.

---

# Accessibility

Symbols should support every operator.

Recognition should not depend on colour alone.

Every icon should remain distinguishable through:

- Shape
- Contrast
- Scale
- Position
- Consistency

Accessibility improves operational reliability.

---

# Consistency

An operator should never have to relearn a symbol.

A warning should always look like a warning.

Status should always look like status.

Information should always look like information.

Direction should always look like direction.

Consistency reduces training.

Consistency improves confidence.

Consistency increases operational speed.

---

# Final Principle

Barqode does not use icons to decorate interfaces.

It uses symbols to create a recognition system.

Operators should recognise the category of a message before reading it.

Every symbol should reduce thinking, improve recognition and communicate with absolute clarity.

When an operator understands the message before reading the words, the system has succeeded.
